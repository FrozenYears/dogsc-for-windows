# 2026-10-25 第 08 轮：P2b DXGI decode surface、D2D scene 与 native overlay

## 目标

降低预览传输开销，接入真实 Media Foundation/D3D11 decode surface，并限制 WebView 端待呈现帧数量；严格区分 decoder surface 与最终显示 surface。

## 完成

- `FrameReader` 尝试启用 `MF_READWRITE_ENABLE_HARDWARE_TRANSFORMS` 和 `MF_SOURCE_READER_D3D_MANAGER`；成功时请求 NV12，读取 `IMFDXGIBuffer` texture，经 staging readback 和 BT.601/BT.709/BT.2020 YUV→BGRA 转换；设备/媒体类型不支持时回退 RGB32 system-memory reader。
- Sidecar 可选创建 owner= Tauri HWND 的 native `WS_POPUP` overlay 和 D3D11 flip-model swapchain；Tauri 按 preview image 的 DOM bounds、window innerPosition 与 DPI scale 发 `R/H` 更新；D2D compositor 与 swapchain 共用同一 D3D11 device。
- 同一 `FrameReader` 对相邻、向前且间隔不超过 0.5s 的 stream 请求顺序读样本；随机/倒退/远距离 seek 使用 `SetCurrentPosition`。JSON 返回实际 sample PTS。
- SourceReader output 和 D2D composite preview 使用 WIC lossless PNG；`media_preview_smoke.ps1` 验证 PNG signature、H.264/HEVC frame、seek、PTS、stream、EOF 和 composite。
- `FrameReader::read_bgra` 直接返回 top-down BGRA；frame、D2D composite 和 export 复用该 buffer，移除 BMP header、反转行和中间像素 vector copy；WIC factory 按持久 reader 复用。
- Tauri `stream-window` 模式隐藏 WebView img；每帧经 FrameSceneEvaluator/D2D composition 后用同设备 `CopyResource` 送入 DXGI backbuffer，再 `Present(1,0)`。D2D composition 失败时保留 raw frame DXGI 呈现；overlay 初始化/呈现失败时回退 PNG/WebView。
- 默认 PNG 路径在请求下一帧前等待 `img.decode()` 与两次 RAF；DXGI overlay 路径等待同步 `Present(1,0)` ack 后才请求下一帧。
- `stream_child_lifecycle_smoke.mjs` 通过 `DOGSC_REQUIRE_DXGI_SURFACE=1` 强制验证 D2D scene、DXGI swapchain + hidden img，并覆盖跨工程 child 回收、窗口 move/resize、scroll occlusion/recovery 与 frame statistics。

## 决议

- H.264/HEVC decoder NV12 surface 由 SourceReader 的 D3D11 device manager 分配；其像素仍 staging-readback 到 CPU，再上传到 overlay device。D2D compositor 复用 overlay device，合成输出纹理经 `CopyResource` 直达 swapchain，避免最终 D2D 帧回读 CPU。
- overlay 的 `Present(1,0)` 使用同步间隔1；`GetFrameStatistics` 读取 `PresentCount`/refresh counters/`SyncQPCTime`，但 Microsoft 文档明确多显示器与其它全屏应用下统计可能不可靠；不能仅凭 Present 或统计声称实机无撕裂。

## 遗留
- 0.2s fixture 的 50–60fps 是短样本的同步 Present ack，不是长时稳态或目标刷新率证据；`vblank` 已可读，但不是帧间隔质量证明。
- decoder NV12 surface 仍 staging-readback→CPU YUV→BGRA upload 到 D2D input；D2D output 通过同设备 `CopyResource` 到 swapchain，无 final composite CPU readback，但端到端仍非 zero-copy。
- 尚无 PresentMon / capture-based no-tear 证据；最小化、DPI、120Hz/VRR、多 GPU、长时 drop<2% 与实际显示撕裂仍未验收。
- `FrameReader` 硬件 decoder/device-manager 分支需在更多显卡与 HDR/视频矩阵上回归；当前像素 smoke 未做逐像素/PSNR 对拍。
