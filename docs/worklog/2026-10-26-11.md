# 2026-10-26 第 30 轮：时间线片段拖拽重排

## 目标

把主时间线现有 native `move` 能力接入用户侧拖拽交互，减少按钮依赖。

## 完成

- timeline segment 按钮启用 draggable 和 pointer fallback。
- drag/drop 与 pointer down/up 都按 segment UUID 调用 native `project edit move`。
- 片段写入 `data-segment-id`，提供稳定的 UI 状态和自动化定位。
- 添加拖拽光标与 hover 视觉样式。
- smoke 保留打开工程编辑按钮断言；后台合成拖拽事件在 WebView 中不稳定，不把它冒充为可靠自动化证据。

## 决议

- native `move` 继续作为唯一顺序真相，前端不直接重排 project JSON。
- pointer fallback 用于 WebView/鼠标实际交互；HTML5 drag/drop 作为桌面拖拽路径。
- 吸附仍未实现；当前只承诺重排，不承诺时间边界吸附。

## 证据

- native CLI 已验证两片段 move：第一片段移动到 index 1 后 JSON 顺序反转。
- 真实 GUI CDP 手工 pointer drag：两段 timeline 顺序发生变化，草稿保存完成。
- `pnpm build`、Tauri Release/NSIS、CTest 7/7 和现有 DXGI/scene smoke 通过。
- 后台合成 drag smoke 曾出现顺序未变化，因此不列为自动化通过项；这保留为 WebView 自动化限制，而不是扩大结论。

## 遗留

- 时间线吸附。
- 拖拽改时长、拖拽裁切和效果轨拖拽排序。

## 下一步

- 继续使用 native timeline editing API 补齐拖拽裁切/吸附，或保持当前重排切片为 partial。
