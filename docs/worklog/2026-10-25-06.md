# 2026-10-25 第 06 轮：P2b 跨工程 stream child 生命周期回归

## 目标

将 Tauri 在项目切换时停止旧 SourceReader stream child 的行为固化为可重复 GUI smoke，而非只依赖人工观察。

## 完成

- 新增 `tests/stream_child_lifecycle_smoke.mjs`：启动 Tauri GUI，通过 WebView2 CDP 打开两个不同工程并依次播放。
- 通过 Windows `Win32_Process.CommandLine` 实际检查 sidecar 子进程：工程 A stream 启动；打开工程 B 后 A child 必须退出；播放 B 后只能观察到对应 B 的 stream child。
- 测试结束时使用 `taskkill /T` 清理其启动的 GUI 进程树。
- 更新功能矩阵，仍将 P2b 标为 groundwork；DXGI 实时呈现和画面性能验收未完成。

## 决议

- 此 smoke 需要 Windows 交互式桌面、已构建的 Tauri Release 可执行文件和两个可解码工程；不纳入默认 CTest，避免在无桌面/无媒体资产的构建节点伪通过。
- 项目切换验收以 OS 进程命令行和 PID 生命周期为准，不只断言 UI 文本变化。

## 证据

- 运行：`node tests/stream_child_lifecycle_smoke.mjs apps/tauri/src-tauri/target/release/dogsc-tauri.exe out/vcpkg-native/p2-frame-smoke/project.json out/vcpkg-native/p2-frame-hevc/project.json`。
- 输出：`stream_child_lifecycle_smoke: project A child exited before project B child started`。
- Node v22.17.1 原生 WebSocket 支持；无新增依赖。

## 遗留

- P2b 仍未接入 DXGI surface、硬背压、丢帧统计、无撕裂与完整暂停/拖动语义。
- 现有 GUI 测试工程来自本机采集资产；CI 需要显式准备等价的 H.264/HEVC 工程对。

## 下一步

1. 实现 DXGI 共享表面和有界帧更新；
2. 记录队列背压与丢帧率；
3. 建立播放同步、无撕裂与 60Hz 验收。
