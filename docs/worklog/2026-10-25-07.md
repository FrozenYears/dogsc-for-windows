# 2026-10-25 第 07 轮：P1b dirty state 与关闭事务闭环

## 目标

修正 project draft 真正性，并将 debounce、失败重试、取消关闭和保存关闭纳入可重复端到端验收。

## 完成

- Native `dirty` 改为比较 committed 与 draft JSON 的语义内容；仅打开工程产生的 clean draft 不再冒充 dirty/recovery。
- `begin` 不再为 clean open 写 recovery manifest；clean reopen 清除陈旧 manifest；损坏/不可解析的 draft 保守判为 dirty。
- `edit-draft` 在保存或 discard 后自动从 committed `project.json` 重建 draft；no-op edit 不产生 recovery 状态。
- Tauri close handler 保存成功后调用 `destroy()`；能力文件加入最小权限 `core:window:allow-destroy`，修复之前 IPC 被 ACL 拒绝的问题。
- 扩展 `tests/project_history_smoke.ps1`：覆盖重复 clean begin、no-op dirty、saved/ discarded 后再次编辑、恢复状态与 manifest 清理。
- 新增 `tests/project_dirty_close_smoke.mjs`：真实 Tauri GUI/CDP + Win32 `WM_CLOSE`，覆盖 clean open、debounce autosave、cancel 保留 draft、破坏 draft 后关闭保存失败仍留在窗口、恢复 draft 后手动 retry 保存并关闭。

## 决议

- 以 committed/draft JSON 内容差异作为 dirty 的权威条件，不以 draft 文件存在作为 dirty 条件。
- 无法解析的 draft 视为 dirty，避免损坏恢复数据被静默丢弃。
- GUI smoke 的 `window.confirm` 返回由 CDP 注入，确定性覆盖 cancel/accept 分支；确认框视觉样式不作为本轮验收内容。

## 证据

- Release clean build：`cmake --build out/vcpkg-native --config Release --parallel --clean-first` 成功。
- Release CTest：7/7 passed；其中 `project_history_smoke` 通过 clean/no-op/save/discard/recovery 边界断言。
- `pnpm tauri:build`：Release GUI 与 NSIS 包构建成功。
- 运行 `node tests/project_dirty_close_smoke.mjs apps/tauri/src-tauri/target/release/dogsc-tauri.exe out/vcpkg-native/p3-style-library/FrameProject`，输出：`project_dirty_close_smoke: clean begin, cancel preserves draft, failed save stays open, retry saves and closes`。
- 测试检查 committed `project.json` 的背景预设已落盘，draft/recovery 文件在成功保存后清除；cancel 后工程保持 dirty，模拟保存失败时窗口不关闭。
