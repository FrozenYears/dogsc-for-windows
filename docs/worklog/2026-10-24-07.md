# 2026-10-24 第 07 轮：P2a 单帧媒体预览接入

## 目标

开始 P2：先建立真实媒体帧读取的最小纵向切片，不伪装成实时预览。实现 `Media Foundation SourceReader → BMP data URI → Tauri img`，为后续 DXGI 播放和共用合成器打基础。

## 完成

- 新增 `tools/capture_cli/frame.cpp`：
  - 从工程 `media.screen.relativePath` 定位媒体；
  - 拒绝绝对路径和 `..` 越界路径；
  - `IMFSourceReader` 请求 RGB32；
  - 启用 `MF_SOURCE_READER_ENABLE_VIDEO_PROCESSING`；
  - 按时间读取视频帧；
  - 最近邻缩放到最大宽度；
  - 生成 32-bit BMP data URI JSON。
- 新增 CLI：

```text
dogsc_capture project frame <project.json|project-directory> <seconds> [max-width]
```

- 增加 Tauri Project Editor 的“预览当前帧”按钮和真实 `<img>` 展示。
- P1a 编辑器与项目库功能保持可用；未把单帧命令误称为实时预览。

## 决议

- 本轮只标记为 **P2a 单帧预览 partial**。
- P2b 的 DXGI 共享表面、播放时钟、拖动、背压、连续解码、非零 seek 和丢帧统计仍未完成。
- SourceReader 的错误路径必须保留明确错误，不能回退到伪造图像。

## 证据

- 首次 H.264 SourceReader 协商失败：`0xC00D36B4`；`ffprobe` 确认 fixture 为 H.264 High / yuv420p / 2560×1600。补充 SourceReader attributes 后重新 clean build。
- H.264 fixture：录制 0.2 秒，`project frame 0 320` exit 0，输出 320×200、data URI 约 341430 字节。
- HEVC fixture：录制 0.2 秒，`project frame 0 320` exit 0，输出 320×200、data URI 约 341430 字节。
- 最新 NSIS 安装包重新构建，约 8.61 MiB；sidecar 829440 字节。
- 从最新安装包 GUI 打开带真实 `screen.mp4` 的工程并点击“预览当前帧”，显示 `960×600 @ 0.00s`，图片 `src` 为 `data:image/bmp;base64,...`。
- P2 native clean build：成功，新增 `frame.cpp` 无 warning/error。
- CTest：`100% tests passed, 0 tests failed out of 7`；现有 CTest 不包含媒体 frame decode，以上媒体命令和 GUI smoke 是额外证据。

## 遗留

- 非零 seek、EOF、损坏文件、音视频同步和连续播放未验收。
- 预览目前绕过 `FrameSceneEvaluator`/`IFrameCompositor`，只显示原始屏幕帧；背景、光标、摄像头、贴图和运镜尚未进入预览。
- DXGI 实时预览、播放时钟、背压和导出共用渲染路径仍未实现。
- 本轮生成的 P2 媒体 fixture、安装目录和临时构建日志待按用户确认清理。
