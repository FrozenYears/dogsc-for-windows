# 2026-10-24 第 03 轮：Tauri 桌面壳首个可运行切片

## 目标

在不重写已验证 C++ 采集管线的前提下，采用 Tauri v2 替代 Electron/WinUI 作为产品壳，先得到可双击启动的 Windows GUI，并把 `dogsc_capture.exe` 接入 sidecar。

## 完成

- 新增 `apps/tauri/`：Tauri v2、Vite、TypeScript、Rust shell plugin 和 Windows NSIS 配置。
- 新增中文录制工作区：输出目录、显示器、帧率、编码器、时长、系统声音、麦克风、摄像头、开始/暂停/继续/停止，以及原生进程日志。
- 配置 `binaries/dogsc_capture` sidecar，准备脚本会从 `out/vcpkg-native/tools/capture_cli/Release/` 复制 `dogsc_capture.exe` 和 FFmpeg DLL，并按 Tauri target-triple 规则命名。
- 新增 Tauri shell 的 spawn、stdin write、kill 权限；应用图标、NSIS 包和构建说明已加入。
- 更新根 README、架构文档和工作日志索引，明确 Tauri 录制壳已完成但编辑器、预览和导出仍未完成。

## 决议

- 采用 **Tauri + C++ sidecar** 作为当前产品路线：Rust 负责桌面壳和进程编排，C++ 保留采集与渲染核心；不直接移植 WPF，也不把 Electron 主进程塞进现有仓库。
- 当前切片先接采集 CLI；D2D 合成器下一步通过 DLL C ABI 或独立 render sidecar 接入，不在本轮伪造完整编辑器。
- 继续使用动态 FFmpeg DLL；sidecar 包含本机构建产物，但发布前仍需完成 FFmpeg 源码、补丁、构建说明与 LGPL 合规材料。

## 证据

- `pnpm install`：Tauri API、shell plugin、CLI、TypeScript、Vite 安装成功；pnpm 11 的 `allowBuilds.esbuild` 已写入 `pnpm-workspace.yaml`。
- `pnpm build`：TypeScript 检查和 Vite 生产构建成功，生成 `apps/tauri/dist/`。
- `pnpm prepare:sidecar`：成功复制 `dogsc_capture-x86_64-pc-windows-msvc.exe`、`avcodec-63.dll`、`avformat-63.dll`、`avutil-61.dll`、`swresample-7.dll`、`swscale-10.dll`。
- `pnpm tauri build`：Rust release 构建成功，NSIS 安装包生成于 `apps/tauri/src-tauri/target/release/bundle/nsis/DogSC Studio_0.1.0_x64-setup.exe`，大小约 2.56 MiB。
- 准备目录中的 sidecar 执行 `--help` 成功，并正确加载随附 FFmpeg DLL。
- 通过重定向 stdin 启动最新 sidecar 实录 2560×1600@30 H.264：依次写入 `P`、`P`、`Q`，输出 `Paused`/`Resumed`，exit 0，最终 31 帧、约 1.03 秒，`ffprobe` 通过。
- 启动 smoke：最新构建的 `dogsc-tauri.exe` 启动 5 秒未退出，取得有效 Windows 窗口句柄 `659750`，随后由本次测试进程结束。
- 现有 C++ Release clean build、6/6 CTest 和 WARP smoke 在前一轮已通过；本轮没有改动其实现逻辑。

## 遗留

- 尚未在 GUI 内完成一次真实录制点击回归；当前已验证 sidecar 文件准备、Rust/Tauri 构建和 GUI 启动，运行时权限与真实按钮→采集→停止保存仍需在 Windows 桌面手动操作。
- 当前输出目录是文本输入，尚未接入 Windows 文件夹选择器。
- 没有项目库、媒体缩略图、时间线编辑、实时 DXGI 预览、SourceReader 导出或 D2D 合成结果接入 GUI。
- `apps/tauri/src-tauri/icons/icon.ico` 是本轮临时生成的 DS 图标，后续可替换为正式产品素材；本轮不删除以保证安装包可构建。
